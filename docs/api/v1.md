# API 契约（v1）

- 状态：兼容期（v1 复用现有路由实现）
- 基地址：`/api/v1`
- 旧地址：`/api`（保留兼容，响应带 `Deprecation: true` 与 `Link: </api/v1>; rel="successor-version"`）

## 1. 版本与探测

每个响应都带：

| Header | 说明 |
|---|---|
| `x-request-id` | 请求 ID；上游传入则沿用，否则服务端生成 |
| `x-api-version` | `legacy` 或 `v1` |

`GET /api/v1/meta` 返回版本、错误码、幂等与限流约定：

```json
{
  "success": true,
  "data": {
    "version": "v1",
    "base": "/api/v1",
    "legacyBase": "/api",
    "status": "compatible",
    "requestIdHeader": "x-request-id",
    "apiVersionHeader": "x-api-version",
    "idempotencyHeader": "Idempotency-Key",
    "errorCodes": ["BAD_REQUEST", "UNAUTHORIZED", "..."]
  },
  "meta": { "requestId": "...", "apiVersion": "v1" }
}
```

## 2. 响应包络

新接口使用统一包络：

```json
// 成功
{ "success": true, "data": {}, "meta": { "requestId": "...", "apiVersion": "v1" } }

// 失败
{ "success": false, "error": { "code": "VALIDATION_ERROR", "message": "...", "details": [] }, "meta": {} }
```

**迁移期说明**：`/api/v1` 当前别名到旧路由，旧接口的响应体保持原结构（例如部分接口直接返回 `{ templates, total }`）。新代码应使用 `src/http/respond.js` 的 `ok/created/fail/paginated`，并按领域逐步迁移。

## 3. 错误码

| code | HTTP | 含义 |
|---|---:|---|
| `BAD_REQUEST` | 400 | 请求不合法 |
| `UNAUTHORIZED` | 401 | 未认证 |
| `FORBIDDEN` | 403 | 无权限 |
| `NOT_FOUND` | 404 | 资源不存在 |
| `CONFLICT` | 409 | 冲突（含幂等处理中） |
| `VALIDATION_ERROR` | 422 | 参数校验失败，`details` 给出字段路径 |
| `RATE_LIMITED` | 429 | 触发限流 |
| `INTERNAL_ERROR` | 500 | 服务端错误 |
| `SERVICE_UNAVAILABLE` | 503 | 依赖不可用 |

## 4. 参数校验

写接口使用 zod（`src/contracts/*`、`src/middleware/validate.js`）。校验失败示例：

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "请求体校验失败",
    "details": [{ "path": "limit", "message": "Too big: expected number to be <=24", "code": "too_big" }]
  }
}
```

已接入：`POST /api/v1/novels/:id/assets/bulk-generate`。

## 5. 限流

- 默认仅在生产开启（`RATE_LIMIT_ENABLED=true` 可强制开启）。
- 全局桶 `api`：`RATE_LIMIT_MAX`（默认 600/分钟）。
- 认证桶 `auth`：`RATE_LIMIT_AUTH_MAX`（默认 30/分钟）。
- 响应头：`RateLimit-Limit`、`RateLimit-Remaining`、`RateLimit-Reset`；超限带 `Retry-After`。
- 当前为进程内计数，多实例部署需接网关或 Redis（Phase 7）。

## 6. 幂等

对 `POST/PUT/PATCH/DELETE` 且带 `Idempotency-Key` 的请求：

- 相同 key + 方法 + 路径 + 用户 → 复用首次结果，响应带 `Idempotent-Replayed: true`；
- 首次请求处理中重复提交 → `409 CONFLICT`；
- 5xx 不缓存，允许重试；
- 默认保留 24 小时（`IDEMPOTENCY_TTL_MS`）。

## 7. 兼容与弃用

- `/api` 与 `/api/v1` 共用 `src/routes/index.js` 的挂载表，避免两套实现漂移。
- 新客户端一律使用 `/api/v1`。
- 旧接口的响应结构会在 Phase 4 之后按领域逐步迁移，迁移前不做破坏性变更。
