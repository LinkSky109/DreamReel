# API 契约（v1）

- 状态：兼容期（v1 复用现有路由实现）
- 基地址：`/api/v1`
- 旧地址：`/api`（保留兼容，响应带 `Deprecation: true` 与 `Link: </api/v1>; rel="successor-version"`）

## 1. 版本与探测

每个响应都带：

| Header | 说明 |
|---|---|
| `x-request-id` | 请求 ID；上游传入则沿用，否则服务端生成 |
| `x-api-version` | `legacy` 或 `v1` |

`GET /api/v1/meta` 返回版本、错误码、幂等与限流约定：

```json
{
  "success": true,
  "data": {
    "version": "v1",
    "base": "/api/v1",
    "legacyBase": "/api",
    "status": "compatible",
    "requestIdHeader": "x-request-id",
    "apiVersionHeader": "x-api-version",
    "idempotencyHeader": "Idempotency-Key",
    "errorCodes": ["BAD_REQUEST", "UNAUTHORIZED", "..."]
  },
  "meta": { "requestId": "...", "apiVersion": "v1" }
}
```

## 2. 响应包络

新接口使用统一包络：

```json
// 成功
{ "success": true, "data": {}, "meta": { "requestId": "...", "apiVersion": "v1" } }

// 失败
{ "success": false, "error": { "code": "VALIDATION_ERROR", "message": "...", "details": [] }, "meta": {} }
```

**迁移期说明**：`/api/v1` 当前别名到旧路由，旧接口的响应体保持原结构（例如部分接口直接返回 `{ templates, total }`）。新代码应使用 `src/http/respond.js` 的 `ok/created/fail/paginated`，并按领域逐步迁移。

## 3. 错误码

| code | HTTP | 含义 |
|---|---:|---|
| `BAD_REQUEST` | 400 | 请求不合法 |
| `UNAUTHORIZED` | 401 | 未认证 |
| `FORBIDDEN` | 403 | 无权限 |
| `NOT_FOUND` | 404 | 资源不存在 |
| `CONFLICT` | 409 | 冲突（含幂等处理中） |
| `VALIDATION_ERROR` | 422 | 参数校验失败，`details` 给出字段路径 |
| `RATE_LIMITED` | 429 | 触发限流 |
| `INTERNAL_ERROR` | 500 | 服务端错误 |
| `SERVICE_UNAVAILABLE` | 503 | 依赖不可用 |

## 4. 参数校验

写接口使用 zod（`src/contracts/*`、`src/middleware/validate.js`）。校验失败示例：

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "请求体校验失败",
    "details": [{ "path": "limit", "message": "Too big: expected number to be <=24", "code": "too_big" }]
  }
}
```

已接入：

- `POST /api/v1/novels/:id/assets/bulk-generate`
- `POST /api/v1/novels/:id/series/plan`
- `GET|POST|PUT /api/v1/novels/:id/episodes/:eid/outline`
- `POST /api/v1/novels/:id/episodes/:eid/compose`
- `POST /api/v1/novels/:id/episodes/:eid/script`
- `POST /api/v1/novels/:id/episodes/:eid/assets`
- `POST /api/v1/novels/:id/seasons/:sid/bulk`
- `POST /api/v1/novels/:id/seasons/:sid/assets/bulk-generate`

契约定义集中在 `src/contracts/novels.js`；路由通过 `validateBody` / `validateQuery` 接入。校验失败统一返回 `422 VALIDATION_ERROR`，`details[]` 带 `path` / `message` / `code`。合法请求仍沿用旧路由的 `{ success: true, data }` 成功包络。

### 4.1 小说域写接口

> 鉴权：所有小说域接口不在公开白名单内；`REQUIRE_AUTH=true` 时必须带 `Authorization: Bearer <token>`。
> 路径同时支持 `/api`（兼容）与 `/api/v1`（推荐）。

| # | 方法与路径 | 请求体 / 查询 | 成功响应 | 主要错误 |
|---|---|---|---|---|
| 1 | `POST /api/v1/novels/:id/series/plan` | `{ episodeSeconds?, episodesPerSeason?, charsPerSecond?, tolerance?, maxChapters?, useLLM?, provider?, model?, force?, forceSeasons?, advanceTo? }` | `200 { success: true, data: { seasons, episodes, episodesPerSeason, episodeSeconds, provider, ... } }` | `400` 缺少正文；`404` 项目不存在；`409` 阶段锁定；`422` 校验失败 |
| 2 | `GET /api/v1/novels/:id/episodes/:eid/outline` | Query：`force?`, `useLLM?`, `provider?`, `model?` | `200 { success: true, data: { title, coreConflict, synopsis, cliffhanger, keyCharacters, provider } }` | `404` 项目/单集不存在；`422` 查询参数非法 |
| 3 | `POST\|PUT /api/v1/novels/:id/episodes/:eid/outline` | `{ force?, useLLM?, provider?, model? }`；默认 `force=true`，显式 `false` 复用缓存 | 同 #2 | 同 #2 |
| 4 | `POST /api/v1/novels/:id/episodes/:eid/compose` | `{ seconds? }`（`0 < seconds <= 3600`） | `200 { success: true, data: { outputPath, url, duration, hasVideo, targetSeconds } }` | `400` 缺少视频素材；`404` 单集不存在；`409` 阶段锁定；`422` 校验失败 |
| 5 | `POST /api/v1/novels/:id/episodes/:eid/script` | `{ provider?, outlineProvider?, stateProvider? }` | `200 { success: true, data: <episode> }` | `404` 单集不存在；`409` 阶段锁定；`422` 校验失败 |
| 6 | `POST /api/v1/novels/:id/episodes/:eid/assets` | `{ image?, audio?, video?, voice?, duration?, resolution?, aspectRatio?, videoTimeoutMs?, scriptProvider? }` | `200 { success: true, data: { episodeId, status, assets } }` | `404` 单集不存在；`409` 阶段锁定；`422` 校验失败 |
| 7 | `POST /api/v1/novels/:id/seasons/:sid/bulk` | `{ task?: 'script'\|'assets', limit?: 1..50, concurrency?: 1..8, onlyMissing? }` | `200 { success: true, data: { task, processed, ok, failed, total, done, remaining } }` | `404` 季/项目不存在；`422` 校验失败 |
| 8 | `POST /api/v1/novels/:id/seasons/:sid/assets/bulk-generate` | `{ limit?: 1..12, concurrency?: 1..4 }` | `200 { success: true, data: { processed, ok, failed, subsetCount, withImages, remaining } }` | `404` 季/项目不存在；`422` 校验失败 |

**字段类型约定**

- 数值字段接受 JSON number 或数字字符串（zod `coerce`）；
- 布尔字段接受 `true` / `false`，以及 `'true'` / `'false'` / `'1'` / `'0'` / `1` / `0`；
- `advanceTo` 仅接受 `source|characters|world|series|episodes|assets|compose`；
- 未声明的字段不参与校验，路由会与原始请求合并后继续透传给 service，避免破坏旧调用方。

**错误包络示例（422）**

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "请求体校验失败",
    "details": [{ "path": "episodesPerSeason", "message": "Invalid input", "code": "invalid_type" }]
  }
}
```

**业务错误说明**：旧路由的业务失败仍返回 `{ "success": false, "error": "<message>" }`（字符串），状态码由 `statusFor` 映射为 `400/404/409`；只有校验层统一返回上面的结构化 `error` 对象。

## 5. 项目归属与公开分享

- 所有以 `:projectId` 标识项目的路由默认执行归属校验：项目不存在 `404`，非所有者 `403`。
- 该规则覆盖 `projects / video / versions / export / analysis / collab / open/v1`；开放 API 使用 API Key 的 `userId` 作为归属主体。
- 公开分享是唯一例外，且必须携带分享 token：
  - `GET /api/v1/collab/shared/:token` → `{ projectId, share }`
  - `GET /api/v1/collab/shared/:token/project` → 只读项目详情（未公开或 token 无效时 `404`）
- 分享接口在鉴权闸门白名单内，无需登录；其余项目接口必须登录。
- 身份只来自 token：路由统一读取 `req.userId`，`body/query` 中的 `userId` 一律忽略（管理动作的目标用户 ID 除外）。
- `ALLOW_ANONYMOUS=false` 时未登录请求直接 `401`；生产环境默认关闭匿名身份。

## 6. 限流

- 默认仅在生产开启（`RATE_LIMIT_ENABLED=true` 可强制开启）。
- 全局桶 `api`：`RATE_LIMIT_MAX`（默认 600/分钟）。
- 认证桶 `auth`：`RATE_LIMIT_AUTH_MAX`（默认 30/分钟）。
- 响应头：`RateLimit-Limit`、`RateLimit-Remaining`、`RateLimit-Reset`；超限带 `Retry-After`。
- 当前为进程内计数，多实例部署需接网关或 Redis（Phase 7）。

## 7. 幂等

对 `POST/PUT/PATCH/DELETE` 且带 `Idempotency-Key` 的请求：

- 相同 key + 方法 + 路径 + 用户 → 复用首次结果，响应带 `Idempotent-Replayed: true`；
- 首次请求处理中重复提交 → `409 CONFLICT`；
- 5xx 不缓存，允许重试；
- 默认保留 24 小时（`IDEMPOTENCY_TTL_MS`）。

## 8. 兼容与弃用

- `/api` 与 `/api/v1` 共用 `src/routes/index.js` 的挂载表，避免两套实现漂移。
- 新客户端一律使用 `/api/v1`。
- 旧接口的响应结构会在 Phase 4 之后按领域逐步迁移，迁移前不做破坏性变更。
