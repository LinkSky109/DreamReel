## 二、P0 需求详细分析

### R01：可视化故事板 / 分镜时间轴

#### 2.1.1 问题与机会
**现状痛点**：当前分镜以纯文本列表展示，创作者无法直观感受镜头节奏、时长分布和衔接点。调整镜头顺序需要逐条编辑，效率低。

**用户证据**：影视创作者习惯使用故事板（Storyboard）工具，时间轴是专业剪辑软件的标配交互。

#### 2.1.2 用户故事
- **US-01**：作为创作者，我希望在时间轴上看到所有镜头的缩略图和时长，以便直观把握影片节奏。
- **US-02**：作为创作者，我希望通过拖拽调整镜头顺序，以便快速尝试不同的叙事结构。
- **US-03**：作为创作者，我希望点击时间轴上的镜头快速定位并编辑，以便高效修改分镜。
- **US-04**：作为创作者，我希望看到总时长实时更新，以便控制成片长度。

#### 2.1.3 功能范围
**包含**：
- 时间轴视图：横向排列镜头卡片，显示缩略图、编号、时长
- 拖拽排序：HTML5 Drag & Drop 调整顺序
- 缩略图：已生成视频自动截取首帧，未生成显示占位图
- 时长调节：每个镜头可微调时长（±1秒）
- 总时长统计：实时显示所有镜头时长之和
- 镜头选中高亮：点击时间轴镜头，右侧面板显示详情

**不包含**（后置）：
- 多轨道时间轴（视频/音频/字幕分离）
- 关键帧动画
- 转场效果可视化预览

#### 2.1.4 验收标准
```
GIVEN 项目有4个镜头
WHEN 用户进入镜头标签页
THEN 时间轴显示4个镜头卡片，按顺序排列，每个显示编号和时长

GIVEN 时间轴显示镜头列表
WHEN 用户拖拽镜头2到镜头4之后
THEN 镜头顺序变为 [1,3,4,2]，总时长不变，API更新项目shots顺序

GIVEN 镜头已生成视频
WHEN 时间轴加载
THEN 该镜头卡片显示视频首帧缩略图

GIVEN 用户修改镜头3时长从5s到8s
THEN 总时长实时增加3秒
```

#### 2.1.5 技术方案
- **后端**：
  - `projectService.updateShotOrder(projectId, shotIds[])` — 批量更新顺序
  - `projectService.updateShotDuration(projectId, shotId, duration)` — 更新单镜头时长
  - 缩略图：视频生成后用 ffmpeg 截取首帧保存到 `storage/thumbnails/`
- **前端**：
  - 新增 `StoryboardTimeline` 组件（可放在 editor.js 内或独立文件）
  - 使用原生 HTML5 Drag & Drop API（无需额外依赖）
  - 缩略图懒加载
- **数据模型变更**：Shot 模型新增 `thumbnailPath` 字段
- **依赖**：无外部依赖，纯前端交互 + 现有 API 扩展

#### 2.1.6 工作量估算
- 后端：2小时（2个API + 缩略图截取）
- 前端：6小时（时间轴组件 + 拖拽 + 缩略图）
- 测试：2小时
- **合计：约10小时**

### R02：单镜头重生成与多版本候选

#### 2.2.1 问题与机会
**现状痛点**：当前批量生成后，某个镜头不满意只能全部重新生成，浪费额度和时间。用户无法对比多个生成结果选择最优。

#### 2.2.2 用户故事
- **US-01**：作为创作者，我希望对单个不满意的镜头重新生成，以便不影响其他已完成的镜头。
- **US-02**：作为创作者，我希望一次生成3个候选版本，以便选择最满意的结果。
- **US-03**：作为创作者，我希望微调镜头描述后重新生成，以便精确控制画面。
- **US-04**：作为创作者，我希望锁定满意的镜头不参与批量生成，以便保护已完成的工作。

#### 2.2.3 功能范围
**包含**：
- 单镜头"重新生成"按钮
- 镜头描述内联编辑（点击直接修改 prompt）
- 多版本候选：一次生成 N 个（默认3，可配置1-5），横向排列对比
- 版本选择：点击候选设为当前版本
- 镜头锁定：锁定后批量生成跳过该镜头
- 生成历史：保留最近3个版本可切换

**不包含**：
- 镜头局部重绘（inpainting）
- 两个版本的融合

#### 2.2.4 验收标准
```
GIVEN 项目有4个镜头，镜头2已生成
WHEN 用户点击镜头2的"重新生成"
THEN 仅镜头2状态变为"生成中"，其他镜头不受影响，额度扣1次

GIVEN 用户选择生成3个候选
WHEN 生成完成
THEN 显示3个视频缩略图横向排列，默认选中第1个

GIVEN 镜头已锁定
WHEN 用户点击"批量生成"
THEN 该镜头跳过，状态保持不变

GIVEN 用户修改镜头描述为"夜景，霓虹灯"
WHEN 点击重新生成
THEN 使用新描述生成，旧描述被覆盖
```

#### 2.2.5 技术方案
- **后端**：
  - `videoService.regenerateShot(projectId, shotId, options)` — 单镜头重生成
  - `videoService.generateCandidates(projectId, shotId, count)` — 多候选生成
  - Shot 模型新增 `versions[]` 字段（存储历史版本路径）
  - Shot 模型新增 `locked` 布尔字段
  - 批量生成时过滤 `locked=true` 的镜头
- **前端**：
  - 镜头卡片增加"重新生成"按钮、锁定开关
  - 候选版本对比视图（横向滚动卡片）
  - 版本切换下拉
- **依赖**：现有视频生成队列，复用 worker 池

#### 2.2.6 工作量估算
- 后端：4小时（版本管理 + 锁定 + 候选生成）
- 前端：5小时（候选对比 UI + 内联编辑）
- 测试：2小时
- **合计：约11小时**

### R03：BGM/音效库与三轨混音

#### 2.3.1 问题与机会
**现状痛点**：当前导出视频只有配音旁白，没有背景音乐和音效，成片不完整，缺乏电影感。用户需要手动在剪辑软件中加 BGM。

#### 2.3.2 用户故事
- **US-01**：作为创作者，我希望从内置 BGM 库中选择背景音乐，以便让成片更有氛围感。
- **US-02**：作为创作者，我希望 AI 根据剧本情绪自动推荐 BGM，以便快速找到合适的音乐。
- **US-03**：作为创作者，我希望添加环境音效（脚步声/雨声/城市噪音），以便增强画面真实感。
- **US-04**：作为创作者，我希望独立调节配音/BGM/音效三轨音量，以便获得最佳混音效果。
- **US-05**：作为创作者，我希望 BGM 自动淡入淡出，以便避免突兀的开始和结束。

#### 2.3.3 功能范围
**包含**：
- 内置免版权 BGM 库（按情绪分类：紧张/温馨/史诗/悬疑/轻快/悲伤，至少20首）
- BGM 元数据：名称、情绪标签、时长、BPM、试听
- AI 情绪推荐：根据剧本概要关键词匹配 BGM 情绪
- 音效库：常用环境音效（至少30个）
- 三轨音量调节：配音/BGM/音效独立滑块（0-100%）
- BGM 淡入淡出：默认各2秒，可调节
- 导出时 ffmpeg 混音（amix 滤镜）

**不包含**：
- 用户上传自定义音乐（版权风险，后置）
- AI 生成原创音乐（依赖外部模型）
- 音效时间轴精确对齐（后置）

#### 2.3.4 验收标准
```
GIVEN 用户进入配音字幕标签页
WHEN 展开"BGM"区块
THEN 显示按情绪分类的BGM列表，每个可试听

GIVEN 剧本包含"紧张""悬疑"关键词
WHEN 用户点击"AI推荐BGM"
THEN 推荐列表前3首标记为"AI推荐"，情绪标签匹配

GIVEN 用户选择了BGM和音效
WHEN 调节配音音量到80%，BGM到30%
THEN 导出视频时按此比例混音

GIVEN 视频时长20秒，BGM时长60秒
WHEN 导出
THEN BGM自动截取前20秒并在结尾淡出
```

#### 2.3.5 技术方案
- **后端**：
  - 新增 `audioService`（或扩展 dubbingService）
  - BGM 库：静态文件存 `storage/audio/bgm/`，元数据存 `src/config/bgmLibrary.js`
  - 音效库：静态文件存 `storage/audio/sfx/`
  - `videoCompositingService` 扩展：支持三轨混音（ffmpeg amix）
  - 项目模型新增 `audioConfig`：{ bgmId, sfxIds[], voiceVolume, bgmVolume, sfxFadeIn, fadeOut }
- **前端**：
  - 配音字幕标签页增加 BGM/音效区块
  - 三轨音量滑块
  - BGM 试听播放器（HTML5 audio）
- **ffmpeg 命令**：
  ```bash
  ffmpeg -i video.mp4 -i voice.mp3 -i bgm.mp3 -i sfx.mp3 \
    -filter_complex "[1:a]volume=0.8[a1];[2:a]volume=0.3,afade=t=in:d=2,afade=t=out:st=18:d=2[a2];[3:a]volume=0.5[a3];[a1][a2][a3]amix=inputs=3[aout]" \
    -map 0:v -map "[aout]" output.mp4
  ```
- **依赖**：ffmpeg amix 滤镜（已确认可用）

#### 2.3.6 工作量估算
- 后端：5小时（audioService + 混音 + BGM元数据）
- 前端：4小时（BGM选择器 + 音量控制 + 试听）
- 素材准备：2小时（20首BGM + 30个音效，可用免费素材）
- 测试：2小时
- **合计：约13小时**

## 三、P1 需求详细分析

### R04：角色表情与动作库

#### 3.1.1 核心功能
- 预设表情库（12种：开心/愤怒/悲伤/惊讶/恐惧/厌恶/平静/思考/微笑/哭泣/紧张/坚定）
- 动作模板（10种：行走/奔跑/坐下/站起/转身/挥手/点头/摇头/拥抱/指向）
- 镜头中选择角色+表情+动作，自动组合到 prompt
- 多角色同框：指定每个角色的位置和动作

#### 3.1.2 验收标准
```
GIVEN 项目有主角和配角
WHEN 用户在镜头中为主角选择"微笑"+"挥手"
THEN 生成prompt自动包含 "character is smiling and waving"
```

#### 3.1.3 技术方案
- 表情/动作库：配置文件 `src/config/characterExpressions.js`
- Shot 模型新增 `characterActions: { characterId: { expression, action, position } }`
- prompt 构建时自动拼接
- 前端：镜头编辑弹窗增加角色动作选择器

#### 3.1.4 工作量：约8小时

---

### R05：场景库与场景复用

#### 3.2.1 核心功能
- 内置场景库（20+：太空舱/古城街道/雨林/赛博城市/海边/雪山/咖啡馆/实验室...）
- 场景元数据：名称、描述、参考图、标签、光线条件
- 用户自定义场景：上传参考图+描述，保存到个人场景库
- 镜头中快速选择场景，自动填充场景描述

#### 3.2.2 技术方案
- 新增 `sceneService`：内置场景 + 用户场景 CRUD
- 场景参考图存 `storage/scenes/`
- Shot 模型新增 `sceneId` 字段
- 前端：镜头编辑增加场景选择下拉

#### 3.2.3 工作量：约6小时

---

### R06：多角色对话配音

#### 3.3.1 核心功能
- 剧本中识别对话格式（角色名：台词）
- 按角色分配不同音色
- 对话节奏控制（停顿时间）
- 多段配音按时间轴拼接

#### 3.3.2 技术方案
- `dubbingService` 扩展：解析对话剧本，按角色生成多段音频
- 用 pydub 或 ffmpeg 拼接多段音频（含停顿）
- 项目模型新增 `dialogueAssignments: { characterId: voiceId }`
- 前端：配音页面增加角色-音色映射表

#### 3.3.3 工作量：约10小时

---

### R07：字幕样式自定义

#### 3.4.1 核心功能
- 字体/大小/颜色/描边/阴影
- 字幕位置（底部/顶部/居中）
- 双语字幕（中+英同时显示）
- 实时预览

#### 3.4.2 技术方案
- 项目模型新增 `subtitleStyle` 配置
- 导出时 ffmpeg subtitles 滤镜传样式参数
- 注意：当前 ffmpeg 无 libfreetype，需用 drawtext 替代或降级方案
- 前端：字幕样式编辑器 + 预览

#### 3.4.3 工作量：约6小时（含 ffmpeg 兼容性处理）

---

### R08：镜头衔接与一致性控制

#### 3.5.1 核心功能
- 上一镜头尾帧作为下一镜头参考图（img2img）
- 全局风格锁定（色温/饱和度/对比度）
- 场景连续性提示

#### 3.5.2 技术方案
- 视频生成时传入 prevFramePath 作为参考图
- 需要 provider 支持 img2img（Mock 可模拟，Runway/Pika 需确认）
- 全局风格参数存项目配置

#### 3.5.3 工作量：约12小时（高复杂度，依赖 provider 能力）

## 四、需求依赖关系与实施顺序

### 4.1 依赖图谱

```
R01(故事板) ──┐
               ├──> R08(镜头衔接) 需要时间轴基础
R02(单镜头重生成) ──┐
                     ├──> R04(角色表情) 需要镜头编辑基础
R03(BGM混音) ────────┼──> R06(对话配音) 需要音频架构
                     │
R05(场景库) ─────────┘
R07(字幕样式) ──> 独立，可并行
```

### 4.2 推荐实施顺序（Sprint 规划）

#### Sprint 1：核心创作体验提升（P0，约34小时）
| 顺序 | 需求 | 理由 |
|------|------|------|

## 五、风险与不确定性

| 风险 | 影响 | 概率 | 应对策略 |
|------|------|------|----------|
| ffmpeg 无 libfreetype，字幕烧录受限 | R07 字幕样式无法完全实现 | 高 | 用 drawtext 替代基础样式，复杂样式后置；或重新编译 ffmpeg |
| 视频 provider 不支持 img2img | R08 镜头衔接无法实现 | 中 | Mock 模式模拟，真实 provider 需确认 API；降级为 prompt 连续性提示 |
| BGM 版权问题 | R03 不能商用 | 低 | 使用 CC0 免版权素材（Pixabay/Freesound），用户上传功能后置 |
| 多角色对话配音拼接质量 | R06 体验不佳 | 中 | 先用固定停顿模板，后续引入情感TTS |
| 前端时间轴性能 | R01 大项目卡顿 | 低 | 虚拟滚动，镜头数>50时启用 |
